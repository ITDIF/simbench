# 用 Modbus Poll 读这台模拟器（5 分钟清单）

日期：2026-10-14　｜　用途：现场最常用的主站工具就是 **Modbus Poll**（Windows，共享软件）。
这份是"照着点就能读到值"的清单，外加**读不到时先看哪三处**——那三处都是实测出来的形状。

## 1. 起虚拟设备（一条命令）

```powershell
# 仓库根，用仓库的 venv
.\.venv\Scripts\python.exe -m simbench examples\virtual-device.csv
```

它会在 `0.0.0.0:5020` 上起一台"隧道机电 1 号机"（unit id **11**，四区都有点：
保持寄存器 hr 0..14、线圈 co 0..3、离散输入 di 0..3、输入寄存器 ir 0..3）。
**这几行数字是量出来的**（`register_span` 逐点算）：`FAN-01` 是 6 个字符 → 占 3 格，
铭牌在 hr 12..14，所以 hr 只到 14。**2026-10-17 更正**：这里原来写的是 "hr 0..17"，
照着填 18 会读到 3 格没声明的地方 → 整条回异常码 2，正是下面第 3 节警告的那种"看着
像模拟器坏了"。
想换端口/只本机可见：`--host 127.0.0.1 --port 5021`。

示例点表**故意是连续的**（没有空洞）：Modbus Poll 起手就是"读 10 格"，点表里有空洞时
那一条请求会**整条**回异常码 2（Modbus 的语义就是"要么整条成功、要么整条失败"），
现场看着像"模拟器坏了"。真有空洞的点表，先跑一次：

```powershell
.\.venv\Scripts\python.exe -m simbench 现场点表.csv --fill-gaps --result 现场点表-连续.csv
```

它把空格补成**看得见的**保留点（`reg16`/`bool`、值 0、名字 `保留<地址>`，界面上也显示），
之后再拿补完的那份去跑。**不是**"读不到就悄悄回 0"——那会把没声明的东西演成设备报的值。

## 2. Modbus Poll 里怎么连

| 项 | 填什么 |
|---|---|
| Connection → Connect（`F3`）→ 类型 | **Modbus TCP/IP** |
| IP Address | `127.0.0.1`（换机器读就用那台机器的 IP；`net show` 能看本机地址） |
| Port | `5020`（上一步 `--port` 给的那个） |
| Slave ID | **`11`**（示例那台设备的 unit id） |

连上后：`Setup → Read/Write Definition`（`F8`）

| 项 | 填什么 |
|---|---|
| Slave ID | 11 |
| Function | **03 Read Holding Registers** |
| Address | `1`（勾着 "PLC Addresses (Base 1)"，对应线缆地址 0）或 `0`（勾掉 Base 1） |
| Quantity | `10`（示例的 hr 0..9 是连续的一段；**想连铭牌一起读就填 15**，即 hr 0..14） |
| Scan Rate | 1000 ms |

点 OK 就该看到值在动：`hr0-1` 是 **float32 CDAB** 的回路温度（sine，60 秒一个来回）、
`hr2-3` 是 float32 ABCD 的风速（ramp 1→8）、`hr4` 是 `11`、`hr5-8` 是 64 位累计电量。

**32 位值的显示**：在显示菜单里把 32 位（float/long）的**字序**设成和点表一致——
示例里回路温度那一行写的是 `CDAB`（两格换位、字节不换），风速那一行是 `ABCD`（默认）。
菜单名随 Modbus Poll 版本略有不同（老版本在 `Display` 菜单下，新版本在 `Display → 32-bit`），
认准"字/字节顺序"那一项即可。设错了看到的是 `1.2e-38` 这类离谱的数，不是"读不到"。

## 3. 读不到时先看这三处（都是实测形状）

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 面板显示 **Exception 4** | Slave ID 写错了 | 我们**回异常码 4**（"设备在，但不认这个 unit"），不是超时。改成点表里的 unit id（示例是 11） |
| 面板显示 **Exception 2** | 地址或数量**跨到没声明的格**上了 | 把 Quantity 调到点表声明的那几格之内；或者先 `--fill-gaps`（见第 1 节）。读**只读点**（示例里的累计电量、铭牌）去写也是异常码 2，那是对的 |
| 连不上 / 一直超时 | 端口或地址不对（防火墙、多网卡） | 界面"网络"页能看到本机地址；启动那一行会打印 `listening on 0.0.0.0:5020`。`--host 127.0.0.1` 只让本机连，`0.0.0.0` 所有网卡都听 |

另外两条容易误判的：

* **值不动**：点表的波形是 `const` 就真的不动（那是设计，不是坏了）。想看它动，用示例里
  的 sine/ramp 那两行，或者把波形改成 `sine` 一类（界面属性面板里改）。
* **一次最多读 125 格**：超过会回异常码 1（协议上限，Modbus Poll 自己也会按 125 切）。
* **同时开多个轮询窗口会被丢请求**（2026-10-17 实测）：同一个 TCP 段里挤了多条请求时，
  pymodbus 3.15.0 **只处理第一条**，第二条既不落盘也不应答——表现就是"第二个窗口一直超时"。
  单窗口轮询不受影响；要同时看多处，先关掉别的窗口。详见规格 §8.1。

## 4. 写值（Modbus Poll 的两个写面板）

* `Setup → Write`（`F6`）写单个/多个寄存器，`Setup → Write Coils` 写线圈；
* 写进去之后，界面上那一行的"波形"列会变成**已停**（这个值现在是主站/人给的，曲线不再顶它）。
  右键那一行 → "恢复波形"就交还给曲线；
* 写**只读点**会被拒（异常码 2）——点表里 `readonly=true` 的那几行就是拿来看的。

## 5. 自动化那一边

`tests/test_modbus_poll_compat.py`（11 条）把上面这些请求**手拼成 MBAP + PDU**打给从站，
逐字节断言应答——不经过任何客户端库，所以它验的就是 Modbus Poll 那一层能看到的东西：
四种区的读、125/126 的上限、写单个/多个、只读点的拒绝、unit 不对的异常码、
以及"点表有空洞时整条请求失败 / `--fill-gaps` 之后读得通"这一对。
