# 新建工程与增删（通道 / 设备 / 点位）实现计划

日期：2026-10-13　｜　范围：界面里能做完整工程**从零搭起来**——新建（空白或骨架）+ 增删
通道 / 设备 / 点位 + 保存/导出。
前置：M1–M6、S7、打包全部完成；本计划**只加"改工程结构"这一件事**，不改既有判定。

> 用户口径：**一次做全**（空白起步与骨架起步都要，增删也都要）。
> 这一条补的是 spec §2 那句"CSV 导入为主，**GUI 手工录入为辅**"——落到现在，"为辅"
> 只做成了**改值 + 改属性**，没有"从零建一份工程"。M2 计划的"不做"表里也没写它，
> 属于当初边界没划清的地方。

---

## 1. 目标与边界

做：

- 工具栏**新建工程**：空白起步，或三种骨架起步（TCP / RTU / S7），骨架 = 一条通道 + 一个
  设备 + 一个点位，名字是占位符、参数是各传输的默认值。
- 设备树右键：空白处 → 添加通道；通道行 → 添加设备 / 删除通道；设备行 → 添加点位 / 删除设备。
- 点位表右键（在既有"恢复波形 / 属性…"之后追加）：添加点位… / 删除点位…。
- 新建的工程没有路径：保存走另存为（已有）；**导出 CSV** 在没有路径时改弹保存对话框。
- 顺手修一条既有缺陷：**打开 / 导入 / 新建会静默丢掉未保存的改动**（见 §2 第 4 条）。

不做（见文末"不做"表）：重命名通道/设备、把点位做成树的第三级、拖拽排序、批量粘贴、
撤销/重做、在**跑着的**通道上增删。

## 2. 现在的事实（读代码 + 实测，非推测）

1. **界面现有的动作只有这些**：全部启动 / 全部停止、导入CSV、导出CSV、打开工程、保存工程、
   检查点表、深色主题；点位表右键只有"恢复波形：<点名>"与"属性…"；设备树**没有右键菜单**。
   一个"加"的动作都没有。
2. **会话只有一条"换工程"的入口**：`Session.load()`，而它第一步是 `_stop_all_locked()`
   （把所有在跑的通道停掉）。`Session.reindex(channel)` 是另一条窄路，它的文档里写死了
   两条边界：**不许**用来对账通道集合（加/删通道必须走 `load()`）、**不许**在被指的那一路
   在跑时调用。所以：
   - 加/删**通道** → 必须 `load()` → 那就要求"没有任何通道在跑"，否则会把正在服务的主站
     一起停掉（M4 已经因为同一个理由拒绝过"改点位地址"）。
   - 加/删**设备/点位** → 目标通道在跑时同样要拒（`SimDevice` 的地址表在 `start_channel`
     时就烘死了，改了点表会与在跑的从站拆成两份真相）；兄弟通道在跑可以走 `reindex`。
3. **写回 + 重校验 + 回滚这条管线已经有两份实现**（`channel_panel._commit`、
   `point_props.apply`），形状都是：改本体 → 全量 `validate_project` → 与改前的 error
   清单**做差集** → 有新增就整体回滚并点名。新增的增删动作必须走**同一个形状**，
   但要新增/删除的是**集合**（不是字段），所以最好的落点是把它抽成一份纯逻辑（§4 Task 1）。
4. **未保存的改动会被静默丢掉**（既有缺陷，实测确认）：`_open_project` / `_import_csv` 直接
   调 `use_project` → `session.load()` → `_dirty = False`，标题上的 `*` 就此消失，关窗也不再
   问。只有关窗（`closeEvent`）问了。加了"新建工程"之后这条更危险（新建 = 主动丢），
   所以本轮一起修：四个"换工程"的动作共用同一个"保存 / 丢弃 / 取消"三选一。
5. **`load()` 会清 dirty**：任何以 `load()` 收尾的结构性编辑，落地之后必须
   `session.mark_dirty()` 补回来，否则"我刚加了一条通道"这件事在标题上不显示、关窗不问。
6. **界面口径是硬约束**（`tests/test_gui_theme.py`、`test_gui_layout_invariant.py`、
   `test_gui_point_props.py`）：不用 QComboBox、状态变化只改文字/颜色/勾选/置灰、定宽槽、
   几何恒定、"置灰不隐藏"。新增加的对话框与菜单**必须**照这套写，并用现有那几种断言方式量。
7. **工具栏那条用例要求每个动作都有文字和图标**（`test_the_toolbar_keeps_a_word_beside_every_icon`），
   图标只能从 `theme.icon(name)` 取，名字不在表里会抛。所以"新建工程"这个动作要**加一个图标**。
8. **本轮发现的既有缺陷（不在本轮修，记在这里）**：`Session._points` 的键是
   `(area, address)`、`Row.key` 是 `(channel, unit_id, area, address)`——S7 的 bool 点带
   **位**（`DBX6.2` / `DBX6.3` 同占一个字节是合法的，`_s7_overlap` 按位判、明确允许），
   于是同一个字节上的两个 bool 点在索引里**互相覆盖**：界面双击改一个可能写进另一个。
   本轮的自动分配把新 bool 点放在**新字节**上，所以默认路径踩不到；但属性面板把位改到
   与邻居同字节之后就能踩到。修它要动 `_points` 的键与 `Row.key`（连带 `write` /
   `set_point` / `restore_waveform` / 面板信号 / 一批用例），是另一个单独的改动。

## 3. 执行前必须先定的口径

| # | 要定的事 | 结论（含理由） | 备选 |
|---|---|---|---|
| 1 | **"新建工程"给什么** | **两种都要**：空白（0 通道）与三种骨架。骨架 = 一条通道 + 一个设备 + 一个点位，点位类型取该传输的"最普通那一格"（Modbus `hr/uint16`、S7 `db1/word`），名字是 `通道1`/`设备1`/`点位1` 这类占位符 | 只给空白（用户得自己配通道参数）/ 只给骨架（想要空白的用户得删） |
| 2 | **骨架里的值谁来填** | **名字与参数在对话框里当场可改**（新建工程对话框 = 起步形态 + 骨架参数区，选"空白"时参数区**置灰不隐藏**）。落地前跑同一条"写回 → 全验 → 差集"的管线，验不过就整体拒绝并点名 | 先落地再让用户去面板改（会先落一个坏工程，且错误得跑第二遍） |
| 3 | **RTU 骨架的串口名填什么** | 那一格**留空**（不替现场猜一个真实 COM 口，依据是 `model.SERIAL_DEFAULTS['port'] = ''` 那条注释），但**对话框不放行空串口名**：按确定会被 `validate_project` 自己的 `serial_port` 挡回来、把原话摆在面板上，操作员当场填。执行期把这条收紧了（见偏离表 D1）：原计划写的是「落地成一条看得懂的 error」，真做下来「新建一份已知不能启动的工程」这个起点不如当场问 | 填 `COM3`（示例里是它，但那是**别人的**点表，照着填等于替现场猜硬件） |
| 4 | **名字/地址/unit 怎么分配** | 全部**自动避开已有的**：通道名 `tcp-1`/`rtu-1`/`s7-1` 递增；TCP 端口从 5020 起跳过已被占的（502 要管理员 + 防火墙，不作为默认）；设备名 `设备N`、unit 取该通道内未用的最小正整数（1..247）；点位名 `点位N`；点位地址取该设备该区里"现有末尾之后"（S7 的 bool 分到**新字节**的 bit 0），这样"加一个点"永远不产生重叠错误 | 固定默认（0x0、unit 1）——第二次添加就撞车，用户得手工改 |
| 5 | **点位的其余字段怎么定** | 默认给全：Modbus `hr`/`uint16`/`ABCD`/`0`/`const`/可写；S7 `db1`/`word`/`ABCD`/`0`/`const`/可写。**加完立刻打开既有的"点位属性…"面板**让用户改名字与其余字段——不另做一个"新建点位"对话框 | 让用户先填 10 个字段再新建（那份表单 `point_props` 已经有了，抄第二份必然漂移） |
| 6 | **增删在什么条件下允许** | 与既有两条编辑路完全同一条：**目标通道（通道级就是任意通道）在跑 → 一律整体拒绝并点名"先停通道"**；都没在跑 → 加/删设备点位走 `reindex(那一行)`、加/删通道走 `load()` | 允许在跑时增删（会把在跑的从站与点表拆成两份真相，且 `load()` 会静默停掉正在服务的主站） |
| 7 | **菜单放在哪** | 通道/设备放**设备树右键**、点位放**点位表右键**——各自放"东西所在的地方"。**不给工具栏加一排小图标**（工具栏几何与那条"每个动作都要有文字+图标"的用例都不动） | 全部塞进工具栏（按钮会多到一排，且每个都要配图标） |
| 8 | **删除要不要问** | **要**，一次带名字与数量的确认（`删除通道 tcp-5020？连同 1 个设备、5 个点位一起删除`）。这是不可撤销的动作，静默删掉一屏点位是现场最难接受的一类 | 直接删（配合"撤销"也行，但撤销是另一个feature） |
| 9 | **空工程长什么样** | 树与表都是空的，**不放假节点、不给一张看着合法的空表当"没装载"**：换工程后日志与状态栏各说一句"空工程：右键设备树 → 添加通道" | 树里放一行灰字提示（假节点会被右键菜单与选中逻辑当成真通道） |
| 10 | **未保存改动的口径** | 新建 / 打开 / 导入 / 关窗**四个动作共用**一个"保存 / 丢弃 / 取消"三选一（默认"保存"，取消则整个动作放弃）。原来只有关窗问，是被实测确认的缺陷 | 只在关窗问（新建/打开/导入继续静默丢） |

## 4. 任务

五个小段，每段自己可验收。前四段是代码，最后一段是文档与打包。

### Task 1　`project/edit.py`：改工程结构的唯一入口（纯逻辑，不碰 Qt）

- 新增 `simbench/project/edit.py`：
  - **分配器**：`next_channel_name` / `next_port` / `next_device_name` / `next_unit_id` /
    `next_point_name` / `next_point_address`（都只读现有工程，纯函数，可单测）；
  - **改动**：`add_channel` / `remove_channel` / `add_device` / `remove_device` /
    `add_point` / `remove_point`，每个都是"改 → 全量验 → 与改前做差集 → 有新增 error 就
    整体回滚并抛 `EditRefused(理由)`"；
  - **新建工程**：`new_project(transport, **values) -> Project`（空白回 `Project()`；骨架是
    一条通道 + 一个设备 + 一个点位，且**整份必须零 error**），`values` 是对话框回填的名字与参数；
  - **默认点位**：`default_point(transport, device, area=None)`（区/地址/类型按口径 4/5 算）。
- `tests/test_edit.py`：分配器逐条（含"第二次添加不撞车""地址取末尾之后""unit 取最小未用"）、
  六条改动的成功路径与拒绝路径（含回滚后**工程一字未变**、被拒时 `dirty` 不变）、骨架的形状。

### Task 2　通道表单与三个对话框

- 新增 `simbench/gui/channel_form.py`：`ChannelForm`（传输三选一的平铺单选按钮 + 名字格 +
  参数格；TCP 是 host/port，RTU 是串口名/波特率/帧格式，S7 是 host/port/rack-slot；
  换传输只改标签、值与置灰，**几何恒定**）。这套写法照 `channel_panel` 的既有行。
- `simbench/gui/new_project.py`：`NewProjectDialog`（起步形态：空白 / TCP / RTU / S7 +
  内嵌的 `ChannelForm`，选空白时表单置灰）、`AddChannelDialog`、`AddDeviceDialog`（名字 + unit）。
- `simbench/gui/theme.py`：加一个 `new` 图标（新建工程用），深浅两套配色。
- 用例：三个对话框的默认值、换传输时几何不变、非法输入（端口不是数、帧格式不成形、
  rack/slot 不成形）当场拒并给一句话。

### Task 3　树与表的菜单 + 主窗接线

- `gui/device_tree.py`：加 `contextMenuEvent` + 可测的 `menu_actions(item)`（沿用
  `point_table._popup` 那个"弹层与构造分开"的写法），设备行带上 unit 的角色数据。
- `gui/point_table.py`：右键菜单追加"添加点位…"与 `删除点位：<点名>…`（新增两个 signal；
  后一条带名字，与"恢复波形：<点名>"同一个口径——一次只可能删右键的那一行）。
- `gui/main_window.py`：
  - 工具栏加"新建工程"；`_new_project` / `_add_channel` / `_add_device` / `_add_point` /
    `_remove_*` 六个槽，统一走"拒绝就点名进日志 + 状态栏，成功就刷新"；
  - `_reload_after_edit()`：结构性改动落地后把会话与五个视图对上、**保住当前选中的通道**
    （加第二个通道的点不要跳回第一个）、并补回 `mark_dirty()`；
  - 点位表选中/树选中跟随。
- 用例：树菜单四种情形（空白 / 通道行 / 设备行 / 没有节点）、表菜单两项的文字与身份、
  添加成功后的三处刷新（树、通道面板、点位表）、被拒时工程与界面都不变、
  当前通道不跳、`dirty` 被置上。

### Task 4　保存 / 导出 / 未保存改动

- `_export_csv` 在没有工程路径时弹保存对话框（原来直接拒绝，新建的工程没有路径）。
- 新建 / 打开 / 导入 / 关窗共用 `_confirm_discard()`；选中"保存"而另存为被取消时，
  **整个动作放弃**（不许一边说没保存一边把改动丢了）。
- 用例：四个动作各一条"有未保存改动时会问"，以及"取消后工程与路径都没变"。

## 5. 执行结果（实测，2026-10-13）

- **全量串行 pytest：1259 → 1329 passed**（`tests/test_edit.py` 33 条、
  `tests/test_gui_new_project.py` 34 条，另有两处既有用例的文字断言按新菜单合同改过、导出那条
  拆成两条），无 skip / xfail。
- **端到端那一条真的跑到了主站**：`test_a_project_built_from_scratch_serves_a_real_master`
  ——空白工程 → 加通道（临时空闲端口）→ 加设备 → 加点位 → 全部启动 → 真 `ModbusTcpClient`
  读 0、写 4242、读回 4242 → 停止。全程只点界面，没有"先手写一份 CSV"的绕路。
- **被测出来的三条既有缺陷**（都不是本轮引入，是这一轮让它变得容易撞上才暴露的）：
  1. **打开 / 导入 / 新建会静默丢掉未保存的改动**：`use_project` → `Session.load` 把 `dirty`
     清回 False，标题上的 `*` 就此消失、关窗也不再问。四个动作现在共用同一个三选一。
  2. **切到空工程（0 通道）后点位表还留着上一份的行**：`use_project` 原来只在"有通道"时挂载
     模型，空工程那条路上模型没被清掉。新增 `PointTableModel.detach()`，空工程就是空表。
  3. **新建的工程导不出 CSV**（没有路径就直接拒绝），而 CSV 正是这个工具跟现场交换点表的方式。
     现在先问一次落哪。
- **新增的一条提示**：导出 CSV 时，若有 TCP 通道的**端口没写在通道名里**（CSV 没有端口列，
  端口靠名字尾数带过去），日志里给一条 note 说明这份 CSV 读回来会是哪个端口——导入那边
  "猜了要说"，导出这边也得说。
