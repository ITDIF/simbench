# S7（S7comm / ISO-on-TCP）从站模拟 实现计划

日期：2026-10-13　｜　范围：新增 **S7 通道**（第三个传输）+ 点位模型/校验/界面/无头 CLI + 验收
前置：M1–M6 已完成（spec §11）；本计划只加新传输，**不改 Modbus 两条路的既有行为**。

> 这是 v1 范围之外的新里程碑（spec §2 明确"私有 TCP/串口协议"不在 v1，§9 的 `Backend` 缝就是
> 为这种事留的）。技术前提已实测，脚本与输出在 `docs/superpowers/notes/2026-10-13-s7-probes.md`
> ——**其中一条推翻了我中途的猜测**（"snap7 服务端只能服务一个 DB"是错的，见 §2.1）。

---

## 1. 目标与边界

做：让**西门子侧的主站/上位机**（Snap7 客户端、组态王/力控一类驱动、PLCSIM 的替身场景）
按 S7comm 读到我们模拟的设备，并且**点位仍然由点表驱动**——波形、值归属、GUI 双击改值、
报文监视、启停这些既有机制在 S7 通道上一条都不少。

不做（见文末"不做"表）：S7comm-plus（S7-1200/1500 的优化块访问）、块上传/下载（程序传输）、
原始以太网（ISO/LLI，非 TCP/IP）、SZL 全表、诊断/时间同步。

## 2. 技术前提（本机已实测，非推测）

明细与可重跑脚本：`docs/superpowers/notes/2026-10-13-s7-probes.md`。四条结论：

1. **协议栈用 snap7 原生库（`snap7.dll`）：它能当服务端，而且不止一个 DB。**
   `python-snap7 1.3` 的 win_amd64 wheel **自带 `snap7/lib/snap7.dll`**（150 KB，LGPL-3.0）；
   3.x 的 wheel 是纯 ctypes 包装、**不含原生库**（实测 34 个条目 0 个 dll）。
   `Server.register_area(area, index, buffer)` 里的 `index` 是**区域编号**（DB 区就是 DB 号），
   `buffer` 必须是 **ctypes 缓冲**；实测 `register_area` 可以挂 **DB1 与 DB2 两个 DB**，
   读 DB1 → `41 48`（我们初始化的 12.5f）、读 DB2 → 另一个缓冲、**读未注册的 DB3 →
   `Item not available`**（正是"未定义地址"该有的形状）。MK/PE/PA 区同样各自独立。
   - 踩过的坑（写进依赖说明）：1.3 的 `__init__` 会 `import pkg_resources`，而
     `setuptools>=81` 已移除它（实测 84.0.0 报 ModuleNotFoundError）⇒ 必须钉 `setuptools<81`。
2. **"我们这边的写"与"主站的写"共用同一块缓冲**：主站 `db_write` 之后我们的 ctypes 缓冲
   立刻变成新值；反过来我们直接改缓冲，主站下一次读就看得见（实测 `buf[8]=0x55` → 主站读到
   `55`）。⇒ 波形 tick 往 S7 区写的落点、以及"谁接管了哪一段"的记账方式，与 Modbus 那套
   （`raw_writer` 改寄存器列表 + `SourceStore`）**同构**，可以复用同一套机制。
3. **拿不到原始报文**：原生服务端只在 DLL 内部组帧，回调给的是**事件**
   （`SrvEvent` 字段实测为 `EvtCode/EvtParam1..4/EvtRetCode/EvtSender/EvtTime`；
   **没有 `EvtParam` 这个字段**，写错的话 ctypes 会静默吞掉回调异常）。
   ⇒ 报**文窗在 S7 通道上给不了"原始字节"那一列**（这是选定 snap7 路线的主要代价，见口径 5）。
4. **验收主站可以不要硬件、也不要原生库**：`pys7 3.1.1` 是**纯 Python 的 S7 客户端**
   （20 个条目、0 个原生库）；再叠上 snap7 自己的客户端当**第二个独立主站**，两份实现同时
   通过才算数。PyPI 上**没有**现成的纯 Python S7 服务端（`s7comm`/`s7server`/`s7-server`
   都查无此包）——所以"自研协议栈"是另一条要自己写 COTP/S7 的路（口径 1）。

## 3. 执行前必须先定的口径（不要带着猜测写代码）

| # | 要定的事 | 建议（含理由） | 备选 |
|---|---|---|---|
| 1 | **走 snap7 原生库，还是自己写 S7 栈** | **走 snap7**：它是这一行的参考实现，真上位机（组态王这类驱动）探的怪东西它都答得上；自研要么长期补桩、要么靠真机撞出兼容问题，而"点表驱动 + 波形 + 归属 + 界面"这些**值钱的部分两条路一样要写** | 自研协议栈：能拿到真 hex 报文（报文窗那一列保住）、无原生依赖、多 DB 随便做——代价是 TPKT/COTP/S7comm 全写 + 兼容性自己担（`pys7` 当主站可以自动化验收） |
| 2 | **S7 通道怎么写进点表**（CSV 的 12 列是合同，不许随便加列） | **沿用 RTU 那套"通道名带参数"的语法**：`s7-1@192.168.0.10:102 0/1`（`name@host:port [rack/slot]`，段间空格——与 `com3@COM3 19200 8E1` 同一个形状）；`rack/slot` 省略时默认 `0/1`。点表列**不加**，现有 12 列照旧 | 给 CSV 加 S7 专用列（要改表头合同 + 迁移旧点表，代价大）；或 S7 通道只能从 project.json/界面建（现场最不方便） |
| 3 | **点位的区/地址/类型怎么表达** | 在**现有列**里表达：`area` 扩成 S7 区名 —— `db1`…`dbn`（DB 号写在区名里）/ `mk` / `pe` / `pa`；`address` 是**字节偏移**（`bool` 写成 `字节.位`，例 `0.3` = DBX0.3）；`datatype` 用 S7 的名字：`bool/byte/word/dword/char/int/dint/real/string`。**同一条通道的点位类型必须与传输匹配**（S7 通道上写 `reg16` = 校验错误，反之 `real` 落在 Modbus 通道上也是错误）——否则"这条点位的值按哪种字节序编"要靠猜 | 保持 Modbus 类型名、在内部映射（`uint16`→`word` 之类）：省一次点表改造，但同一张表里两种方言混着看，现场最容易填错 |
| 4 | **`word_order` 怎么办** | S7 没有字序概念（一律大端）：S7 通道的点位**只认 `ABCD`**，其它值给一条**警告**（不拦启动，与单寄存器类型填字序的既有口径一致） | 当作错误拦下（更严，但现场从 Modbus 点表改过来时会被一堆字序卡住） |
| 5 | **报文窗在 S7 上显示什么** | 显示**事件行**：方向用 `读/写`，摘要写 `DB1 读 4B @0` / `DB1 写 2B @4`（`EvtParam1..4` 里就是区/DB/偏移/长度），"原始字节"那一列**空着并保持列宽**（口径 4：槽位装不下就改文案，不加宽不截断）。**要点**：这一列的合同因此变成"TCP/RTU 给 hex、S7 给事件摘要"，得写进 spec §7 | 在 TCP 层再抄一份 TPKT/S7 解析只为抓 hex（多一层、多一处会与 DLL 判不一致的地方，且解析错就是"界面演了没发生的事"）；或干脆自研栈（口径 1 的备选） |
| 6 | **验收与真机** | 自动化：`pys7`（纯 Python 主站）+ snap7 客户端（第二个独立主站）双主站跑同一张验收表；真机冒烟：你手上那套上位机（组态王/力控/WinCC 或 Snap7 示例客户端）连 `本机IP:102`，读 DB/位/REAL、写值看波形是否被顶掉。**端口 102 在 Windows 上不需要管理员**，但首次监听会弹防火墙授权——冒烟时先放行 | 只用 snap7 客户端（省一个依赖，但少一份独立实现的兼容性证据） |

**这 6 条定了才动手**。另外两条我先按既有口径定死、不占你的决策位：`snap7` 的 import 只许
出现在 `backend/`（架构守卫把 `snap7` 加进"只许 backend"那张清单）；S7 通道与 RTU 一样
**不进** `net/` 的设备 IP 与额外监听那条路（串口/S7 都没有"本机再挂几个 IP:端口"这回事）。

## 5. 任务

### Task 1：模型与往返（`S7Channel` / CSV / JSON / 校验）
1. `model.py`：`S7Channel`（字段：`name/host/port=102/rack=0/slot=1/devices`；`type` 仍不设字段，
   写盘时由 `channel_transport()` 补 `"s7"`，与 `SerialChannel` 同一条口径）；`channel_transport()`
   加 `isinstance(ch, S7Channel)` 分支；S7 区名/类型名的**转换**函数（`parse_s7_area("db3")`、
   `s7_type_for(area, datatype)`），判定留给 validate。
2. `csv_io.py`：通道名语法 `name@host:port [rack/slot]`，与 `parse_serial_name` 并列成
   `parse_s7_name`；导出时把 host:port 与 rack/slot 烘回名字（**不丢参数**）。语法坏掉带行号拒。
3. `json_io.py`：`type == "s7"` 时读写那几个键（`port`/`rack`/`slot` 必须 JSON 整数）。
4. `validate.py`：区名白名单（`db1`..`dbn`，n 上限定 4095？见口径讨论）、字节偏移 0..65535、
   `bool` 的位 0..7、类型与传输匹配、`word_order` 非 ABCD 给 warning、`(host, port)` 重复沿用。
5. 用例：`test_s7_model.py`（默认值、往返、语法、坏语法带行号）、`test_s7_validate.py`（逐项边界 +
   一条"既有 Modbus 工程一条新错误都不多"的回归）。

### Task 2：`codec/s7_codec.py`
1. 纯函数：`encode/decode`（按 S7 类型 → 字节；`bool` 是**位**、`real` 是 IEEE754 大端 4 字节、
   `dint` 有符号 4 字节、`word/dword` 无符号、`string` 是 S7 STRING 还是裸 ASCII——**口径 3 的
   延伸**：建议先做"裸 ASCII 定长"并写清与真 S7 STRING（首字节是长度+最大长度）的差别）。
2. 用例：`test_s7_codec.py` —— 12.5f = `41 48 00 00`、-1 的 dint = `FF FF FF FF`、位读写、
   string 往返、越界与类型不符报领域错误（消息带点位名/类型名）。

### Task 3：基类抽钩子（TCP/RTU 行为一个字不变）
1. `modbus_base.py`：把 `_note_master_writes(raw)`（帧 → 归属）改成 `_note_master_activity(...)`
   形式的钩子：TCP/RTU 仍按帧切（`_split_frames`/`_parse_frame`），S7 由子类用事件驱动。
2. 验收=既有全套用例不改且全绿（M5 Task 3 同一套做法）。

### Task 4：`backend/s7_server.py`
1. `S7Backend(ModbusBackendBase)`：`_probe()`（起之前确认端口可用——snap7 的 `start_to` 自己
   绑端口，失败要翻译成人话）、`_create_server`（建 `Server()` + 按点表注册区域缓冲）、
   `_await_ready`（`get_status()` 起没起来）、事件回调（报文事件 + 归属）。
2. **区域缓冲按点表算大小**：每个 DB/区一块 `ctypes` 缓冲，大小 = 该区点位的最大 `offset+size`
   向上取整（含少量余量），并**留一个锁**（`lock_area/unlock_area` 或自己一把 threading.Lock）
   —— tick 在 loop 线程写、DLL 在自己的线程读，跨线程共享缓冲必须有纪律（spec §13 的老账）。
3. `describe()`：`192.168.0.10:102 rack 0 slot 1`（状态栏/命令行同一句话）。
4. 用例：`test_s7_backend.py` —— 起停、`pys7` 主站读写（DB/位/REAL/string/多 DB）、未定义地址、
   CPU 状态、stop 释放端口、起失败的报告。

### Task 5：工厂 + Session + CLI + net 让路
1. `make_backend` 加 "s7"；`Session`/`__main__` 走同一条（`--list` 打印 S7 通道那一行）。
2. `net/endpoints.py` 与 `net/startup.py` 的过滤条件从"非 tcp"扩展为"只认 tcp"（S7 与 RTU 同样
   不过问设备 IP）——M5 那两条现成的判据改一个条件即可，附用例。
3. 用例：混装工程（Modbus TCP + RTU + S7）三路独立启停。

### Task 6：界面
1. `channel_panel.py`：S7 行三格（host / port / `rack.slot`），TCP/RTU 行一个字不动；写回与回滚
   沿用 `_commit` 那条路。
2. `packet_view.py`：事件行的"原始字节"列留空（列宽与列序不变）。
3. 点表在 S7 通道下的显示：`原始寄存器`列改成该点字节的 hex（列头不动，内容是字节）；
   `当前值` 按 S7 类型解码。
4. 用例：几何恒等（四态）+ 写回/拒绝 + 三个传输混装时 TCP 行逐格不变。

### Task 7：双主站验收（真主站）
`test_integration_s7.py`：`pys7` 与 snap7 客户端各自跑同一张表——读（DB 字节/位/REAL/DINT/STRING、

| # | 计划原文 | 实际落地 | 为什么 |
|---|---|---|---|
| D1 | 只写了"`host:port` 与串口名靠有没有 `:` 分开" | 加了**"有 `@` 没冒号 + 这一行的区/类型是 S7 写法"就带行号拒绝**的判据 | `name@host` 与"串口名叫 host"语法**一模一样**，只问通道名分不出来；同一行的 `area`/`datatype` 是现成证据（`db1`/`real` 不是 Modbus 写法），不利用它就等于让一路 S7 静默变成开不起来的串口 |
